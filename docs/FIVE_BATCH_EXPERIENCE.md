# 五批能力交付说明

2026-09-07。保持 `/api/v2`，新存档结构版本为 7。

## 入口与行为

| 能力 | 网页入口 | 实现与边界 |
| --- | --- | --- |
| 相关记忆 | 历史与记忆 → 相关记忆 | 人物、地点稳定 ID 与有原文证据的别名；中文词项、实体、主题、事项排序。保留最近 24 条叙事事实、8 场摘要，另外补取必需证据与最多 16 条相关历史事实。 |
| 后台整理 | 相关记忆 → 暂停／继续 | 当前 Provider 按固定范围、每批 50 条整理；保存缓存、游标、版本、原文引用。每运行时最多 1 个批次，前台行动优先。候选不能自行结清承诺。 |
| 历史与回顾 | 历史阅读／行动记录／章节回顾 | 场景稳定游标默认 20 条、行动记录 50 条；阅读页不跟随 SSE 跳动。按实际进入的阶段整理章节，按需生成回顾并缓存；只使用对应历史范围的事实及角色快照。 |
| 恋爱设置 | 开局与设置 | `off / player_led / organic`，默认自然发展，不强制恋爱对象。关闭只影响未来。 |
| 等待优化 | 设置 → 普通观察与闲聊的审查 | 低风险结构化计划合并审查；发现结算、资源、重大授权、知识披露或 NPC 后果时使用完整流程。保留关闭开关。 |
| 正文依据 | 最新场景与历史正文 → 事件依据 | 段落与陈述 ID、原始事实 ID、客观事件／人物说法／未确认类型。核对实际正文与段落绑定，润色不能破坏引用；旧正文保留原文并标记未建立引用。 |
| 存档与分叉 | 历史与记忆 → 存档与分叉 | `.srpg.json` 固定到明确检查点，含完整事件前缀和投影；排除账户凭据、运行锁和队列投递记录。导入创建独立存档并验证重映射后的重放结果；冻结报价只重映射有完整原状态支持的校验哈希，不更换骰点。 |
| 恢复 | 存档与分叉 → 恢复缺失正文／未执行行动 | 导入不投递历史回合，托管暂停。提交前失败和已提交缺失正文分别恢复；后者不重新规划、扣费或执行行动。 |
| 路线 | 故事中的候选路线；进展中的剧透大纲 | 默认示例 8 节点，最多 12 节点，DAG、明确终局、非终局兜底。条件只支持结算、里程碑、有证据的断言及 all/any。未知不等于假；所有候选均需确认。 |
| 历史分叉 | 历史场景 → 从这一场分叉 | 用完整初始化快照和事件前缀恢复当时状态；旧选择处保留未确认状态，不带入后果。不能证明初始化完整的旧节点仍可读，拒绝推测分叉。 |
| 资源与技能 | 角色面板 → 查看代价 → 执行 | 体力、伤势、金钱、唯一物品、属性与技能；登记障碍、交易、奖励、设施。服务层与 MCP 支持完整初始面板，旧档确认后启用。报价、骰点、结果和消耗持久化并事务提交；展示灵力、电量、法术槽和唯一物品消耗，旧选择不授权另一项高代价行动。 |
| NPC | 人物动态与预警 | 个人观察、转述、推断、相信／怀疑、隐瞒及来源。角色只读取自身资料和可知来源；已有审查登记目标、承诺与阵营计划，按事件、故事时间或阶段触发，每回合最多一次调用、两个主体。 |

选择后仍只推进一场，托管需要玩家恢复；阶段超时仍暂停；正文只在校验后发布；正文重试不改变世界状态。

## 默认资源规则

- 体力上限 100；休息 30 分钟恢复 30，长休 480 分钟回满。
- 伤势 0–3；轻伤 −2、重伤 −4，失能不能执行冒险判定。
- 属性各 2、技能各 1。判定为 d20 + 属性 + 技能 − 伤势修正 + 规则加成，难度 10／14／18。
- 潜入消耗 10 体力／20 分钟，交涉 5／15，强攻 20／10，调查 5／15。失败仍扣尝试成本，留下警戒、关系或伤势后果。相同策略和登记条件不能靠改写文字刷新判定。
- 修仙：灵力 30，术式消耗 5、判定 +2；调息 30 分钟恢复 10。
- 奇幻：法术槽 3；照明给调查与开锁 +1，长休结束照明；护盾抵消一次强攻失败的伤势；开锁使用登记障碍判定。法术消耗 1 槽，长休恢复。
- 科幻：电量池和工具前置条件；入侵消耗 10 电量，失败增加追踪；充能要求登记设施。
- 悬疑：与目标登记关联、来自至少两个来源回合的已核实证据，给调查或交涉 +2；传闻不提供加成。这是结构化来源检查，不能证明自然语言材料在现实意义上独立。

规则集和版本保存在资源状态中，独立于叙事故事包。首版为有限模板，不含职业树与自动经验升级。初始障碍、物品及交易奖励配置是规则登记入口；模型不能直接改余额、持有人或骰点。

NPC 核心不可逆后果先产生玩家可感知的预警事实，再留出至少一次玩家行动与 60 故事分钟。规划和报价不能越过待处理的关键时间边界。有事件依据的干预可以取消目标，现实等待不推进故事时钟。

## 证据、迁移与恢复

关系、里程碑、事项、分支断言和待处理 NPC 目标的来源属于必需证据。必需上下文超过 80,000 字符时返回 `MEMORY_REQUIRED_BUDGET_EXCEEDED`；可选命中仅在总额 100,000 字符内加入，不静默裁掉必需证据。索引和后台摘要只是检索辅助。

升级逐批经过版本 3–7，每版修改前写文件及数据库备份，再追加可重放迁移事件。旧阶段结论、事实及正文保留；旧资源不倒算，旧知识只补可证明的亲历或见证。配置、完整角色资料、关系、阶段、选择、资源、断言、知识和 NPC 状态纳入重放校验。知识事件按增量记录，数据库检查点压缩保存，导出仍是普通 JSON。

检查点包括“行动已提交、正文待生成”和“正文发布完成”等节点。导出返回实际场景／事实序号；恢复未发布节点只补正文。索引和缓存可重建。历史检查点重建要求完整初始化和事件前缀，不能证明时不开放分叉；重建旧节点不会改变默认导出的最新节点。

## API 与 MCP

新增 API 位于 `apps/api/experience-routes.ts`，所有故事入口检查存档权限，并复用同一服务层。

- `GET history / scenes/:sceneId / actions / chapters / memory / checkpoints / recovery`
- `POST chapters/:stageId/recap / memory/index / facts/read / checkpoints/rebuild`
- `GET save`、`POST /api/v2/saves/import`、`POST forks`
- `PUT graph`；原阶段提案接口额外返回 `proposals[]`
- `GET resources / npcs / metrics`、`POST resources/quote / resources/enable`
- 原 `POST turns` 支持 `resourceIntent`，仍复用队列、选择确认及幂等机制。

MCP 同步提供历史、记忆、回顾、检查点重建、导出导入、分叉、路线读取与确认、大纲编辑、面板、报价、资源启用、人物动态及观测工具。旧文本接口存在歧义时仍返回冲突。

## 验证

使用 Node.js 24+：

```powershell
npm test
$env:PLAYWRIGHT_CHANNEL='chrome'
npm run test:ui
npm run build
npm run test:experience-long
npm run test:experience-real
```

真实长测失败后可以 `npm run test:experience-real -- --resume` 续跑同一隔离存档。结果见 `reports/acceptance/FIVE_BATCH_ACCEPTANCE.md`。

检索、关键词规则、引用存在性和模型复核都不是任意自然语言一致性的证明。真实长测使用固定大纲，以资源行动和长休跨三个故事日；路线与 NPC 行为另有确定性集成测试，不能等同于多题材开放剧情的长期质量评估。
